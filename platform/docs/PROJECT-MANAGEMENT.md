# Создание проектов в мастер-кабинете

Администратор и команда: **Мастер → Главная → Создать проект**. Сотрудник получает доступ к созданному им проекту; остальные проекты не становятся ему доступны. Клиенты не могут создавать проекты или менять подключения.

## Порядок настройки

1. Проект: название, клиент, тип (лидогенерация, интернет-магазин, социальные продажи), часовой пояс, валюта и даты.
2. KPI: месячная цель, максимальная стоимость результата, бюджет и пояснение. Плановые значения отделены от фактической статистики.
3. Каналы: Meta, Google, SMM; CRM не требуется, CRM TOYS либо KeyCRM. CAPI доступна для CRM TOYS и Meta.
4. Бриф: продукт, аудитория, география, язык, контакты, текст и ссылки на бриф, проектную таблицу и существующую папку Drive.
5. План и материалы: задачи, сроки, ответственные, статусы, стратегия, анализ конкурентов и креативный бриф.
6. Проверка: обзор заполненного и отсутствующих необязательных данных.
7. Подключения: источники проверяются отдельно после сохранения проекта.

«Сохранить и продолжить позже» создаёт обычный проект с дашбордом и выбранными подстраницами. Настройки можно повторно открыть из обзора мастер-кабинета или раздела «Проект» в дашборде. Старое окно выполненных/невыполненных задач не открывается автоматически.

Ссылки на Drive и Sheets сохраняются как ссылки: папка автоматически не создаётся, содержимое таблицы по ссылке автоматически не импортируется. Незаданные показатели не подменяются нулями.

## Источники

- **Meta:** ID кабинета, доступного агентскому токену платформы. Проверяются доступ, валюта и часовой пояс; импорт использует существующее расписание рекламных снимков.
- **Google Ads API:** Customer ID, Client ID, Client Secret, Refresh Token, Developer Token и при необходимости Manager ID. Это прямое API-подключение с проверкой доступа, а не самостоятельная выдача OAuth-разрешений приложению.
- **Google CSV:** альтернативный ручной импорт до 2000 строк, с предварительным просмотром и явным подтверждением. Заменяет только импортируемый диапазон дат данного проекта; переход с API требует сначала отключить API.
- **KeyCRM:** API-ключ, воронка, квалифицирующие статусы и необязательный точный фильтр `utm_source`. Первый импорт выполняется в фоне, затем по расписанию. Импортируются квалификации без выдуманных продаж и распределения по кампаниям. Историческая дата квалификации ограничена наблюдениями интеграции. Неполный импорт не заменяет последний полный снимок.
- **CRM TOYS:** готовая внутренняя CRM; ключ приёма заявок сайта показывается один раз. В интерфейсе есть endpoint и пример запроса. Хранится хэш ключа.
- **CAPI:** подключённый Meta-кабинет, принадлежащий ему Dataset и токен. Токен шифруется; доступ проверяется без отправки событий и повторной отправки истории. Доставку первого события нужно проверить в Events Manager.

Один рекламный кабинет нельзя одновременно назначить двум проектам через этот мастер. Отключение источника прекращает его работу, сохраняя уже импортированную историю. Тип и часовой пояс защищены после подключения; часовой пояс остаётся защищён после импорта CRM-карточек.

## Хранение и доступ

Добавочная миграция `0039_project_management.sql` создаёт шесть таблиц настройки/подключений/импорта. Настройки, материалы, назначение создателя и аудит создаются атомарно. Повтор запроса с тем же ключом идемпотентности не создаёт дубль. Редактирование проверяет версию настроек и действующие права в транзакции.

Секреты KeyCRM, Google и CAPI шифруются существующим `CRM_ENCRYPTION_KEY`, не выдаются в GET и не сохраняются в browser storage. Приватные динамические URL `project-*` требуют авторизации; Pages направляет их в Worker. При изменениях настроек и подключений обновляется ревизия и сбрасывается сохранённый кэш данного проекта.

Доступы клиентов выдаются отдельно существующим разделом «Доступы»; команда выдаёт доступ чтения только к своим проектам. Создание проекта не отправляет приглашения, не создаёт внешние аккаунты и не запускает рекламу.

## Выпуск

- `python scripts/configure-project-management.py schema` — только добавочная схема, без тестовых проектов.
- `npm run unified:build` и `npm run unified:test`.
- `npx playwright test --config recovery-tests/project-management.config.mjs` — desktop/mobile, права, сохранение/редактирование, свежие материалы, подключения.
- Сначала опубликовать Pages gateway из коммита с маркером `dynamic-managed-projects-v1`, затем Worker. Release guard проверяет это условие.
