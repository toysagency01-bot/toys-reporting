## Покрытие

Одна SQL-команда читает согласованный снимок семи источников:

- `finance_state` — ревизия;
- `finance_records` — счета, проекты, правила, операции, включая удалённые записи;
- `finance_writes` — служебные записи дедупликации финансов;
- `finance_bank_state` — состояние и банковские остатки, без технического lease;
- `finance_bank_rates` — исторические курсы;
- `audit_log` — только действия `finance.*`;
- `project_invoices` — только инвойсы, на которые ссылаются распределения оплат.

Вся БД, CRM, файлы инвойсов/вложения и секреты в копию не входят.
Читаемые месячные итоги, ЗП и бюджеты рассчитаны тем же `finance/model.js`, что и
платформа. Точные исходные значения, JSON, IDs, версии, tombstones и даты остаются
в архиве. Пустые листы зарплат/распределений/бюджетов означают отсутствие таких
данных в исходном снимке; ничего не дополнять предположениями.

## Формат и целостность

Листы 2000..2012 — управляемые текущие представления. Лист 2099 «Архив» хранит
полный JSON каждого нового снимка частями до 30 000 UTF-16 единиц. Колонки:
SHA-256, время UTC, номер части, число частей, JSON. Старые снимки не очищать.
Повтор того же SHA не добавляет второй архив. Новые данные и архивная запись
записываются одним atomic Sheets batchUpdate. Google-таблица не меняет источник.

SHA-256: UTF-8 JSON объекта `tables`, рекурсивная сортировка ключей, без пробелов,
без ASCII-экранирования Unicode. Скрипт подготовки проверяет checksum и IDs
существующих листов. Строковые значения записываются как `stringValue`, поэтому
содержимое из финансов не исполняется как формула Sheets.

Исходный подтверждённый снимок: revision 4, 69 finance_records
(8 счетов, 17 проектов, 36 правил, 8 операций), 178 finance_writes, 12 курсов,
8 записей аудита, 0 связанных инвойсов. Три архивные части были прочитаны обратно
из Google, восстановлены в JSON и сравнены с оригиналом и SHA-256.

## Обновление

Настроена облачная автоматизация ChatGPT «Бэкап финансов TOYS» с интервалом один
час, timezone Asia/Tbilisi. Она использует подключённый Google Drive и облачную
среду с разрешённым Cloudflare API/готовым CLOUDFLARE_API_TOKEN. Это отдельное
расписание ChatGPT, а не новый cron в production Worker. Зависит от доступности
подключений и облачной среды. Состояние первого автоматического запуска нужно
подтверждать по run history, не только по `is_enabled`.

Для чтения источника из `platform`:

```sh
python scripts/export-finance-backup.py /workspace/finance-google-backup/snapshot.json
node scripts/prepare-finance-sheets-backup.mjs SNAPSHOT REQUESTS METADATA_JSON [archive-present]
```

Выходные файлы с финансовыми данными держать вне Git и с правами 0600.
Метаданные листов и наличие SHA в архиве читать непосредственно перед записью.
Массив из REQUESTS передавать подключённому Google Drive batch_update_spreadsheet,
не печатать пользователю. После записи перечитать manifest и архив, сверить
число частей, checksum и исходные строки. При ошибке сохранить последнюю копию
и явно сообщить, что обновление не выполнено.

Прямой запрос немедленного запуска через automations_run_now вернул 404
`Action not found`; это не доказательство выполнения автоматизации. Для проверки
первый запланированный запуск сдвинут на ближайшую минуту, далее раз в час.

Первый запланированный запрос фактически поступил в исходный чат и был выполнен.
Снимок от `2026-10-27T06:45:36.594903+00:00` записан в Google; все три его части
прочитаны обратно и совпали с исходным JSON и checksum. Первая архивная версия
сохранена, всего две версии. Повторно сверены 8 счетов, 17 проектов, 36 правил и
8 операций. Это подтверждает первый полный цикл обновления, но не гарантирует
будущую доступность Google/Cloudflare или исполнения расписания ChatGPT.

## Восстановление

Выбрать SHA снимка, собрать все его части по порядку, распарсить JSON, проверить
полноту, schema и SHA-256 объекта tables. Вначале восстановить во временную БД и
проверить счета, валюты, версии, связанные записи и расчёты. Полное восстановление
платформы потребует остальной БД и секретов из другого защищённого источника.
Автоматически писать данные Google Sheets обратно в production запрещено без
отдельного запроса пользователя на восстановление.

## Проверки

Четыре автоматических сценария: сохранение удалённых данных, защита от формул из
строк, обновление текущего состояния без стирания архивов и Unicode roundtrip.
Проверены Google metadata, права, IDs листов, диапазоны, форматы и архивный
roundtrip. Визуальная проверка через интерфейс Google не выполнялась; формат
проверялся через Sheets CellData.
