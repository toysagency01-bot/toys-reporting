# Lead status selection inside the card

The existing status field was below the request and comments. It is now the first control under the lead's name/contact details, with a Save button immediately beside it. The control remains visible while scrolling the editable form. Request, comments and history are preserved below the form. A successful save closes the card, reloads the CRM board and confirms the saved status. The same form supports all stages of the selected board and board transfers; sale amount/currency validation and explicit qualification rules are unchanged. Mobile selects use a 16px font and controls have at least 44px touch targets.

QA: 203 automated tests and three existing CRM browser scenarios passed, covering stage changes, sale validation, counters and persistence in embedded and master CRM. Additional local browser QA used the 15-stage TOYS pipeline with a long request and eight long comments: status and Save were visible immediately on desktop and mobile; a touch interaction opened the card and saved a rejection on mobile; qualification counters and state after reload matched CRM. Desktop/mobile screenshots were inspected. Synthetic local fixtures only; no production lead mutations or provider requests. Direct browser access to production remains blocked by environment network policy; the active deployment was confirmed through Cloudflare API.
